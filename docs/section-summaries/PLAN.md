## 作るもの
1. 後処理 build_section_summaries（新規 src/section_summaries.py、score.py の後処理一覧と画面の後処理の一覧に登録）
   - Section ごとに gemma4 で要点（1〜2 文・80 字以内。X16 の指示: 対象・定めている事項・参照先の番号を含める）を作り、Section.summary・summary_model・summary_at に書く
   - 入力は節の見出しの経路＋所属チャンク（主所属）の本文の先頭 3,000 字。章（level 1）は子の節の要点も入れて章の要点にする
   - 本文の指紋（sha1）を summary_src に持ち、変わっていない節は作り直さない。同時要求は 4 本まで
   - 既定の検索の文脈に summary が出ないことを確かめる（出るなら除外キーに足す。夜間の evidence と同じ扱い）
2. 参照追跡の選び方の設定 reference_doc_select（rerank＝今の方式 / summary_list＝新方式）と reference_doc_max（既定 4）
   - summary_list: 文書だけを指す参照について、参照先の文書の節を候補にし、リランカー（質問＋参照の一文 対 見出し＋要点）で上位 20 → gemma4 に「質問・参照元の節（見出し＋参照の一文の前後）・既に手元にある節・候補の一覧（番号・文書・節の経路・要点）」を見せ、最大 4 件の番号を JSON で返させる（X16 の指示を写す）→ 選んだ節ごとに主所属のチャンクからリランカーで 1 件
   - 節の数が閾値（既定 30）を超える文書は、章の要点で章を選んでから、その章の中の節を同じ一覧で選ぶ（2 段）
   - LLM が失敗・空なら今の方式（rerank）に戻す。要点が無い節はリランカーの点数だけで並べる
   - 2 ホップ目も同じ。参照で足す総数の上限は、参照元 6＋参照先 4 を目安に文字数予算で守る
3. graph-evidence の参照展開の表示に「選び方（一覧選択）」と選んだ理由の欄を足す（trace の via に selection=summary_list）
