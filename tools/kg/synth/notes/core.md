## 3. 通った形と通らなかった形

通った形は 2 つである。

1. 試運転の場面の語だけで「どう扱うか」と聞き、答えを規定の条に置く。答えの条は「当該品」「記録」「基準に定める条件」と書いており、過給機・試運転・回転速度の語を持たない。
2. 起点に管理番号や様式番号が出て、答えは番号だけで引く表にある。表には名称を書かない。質問は表の見出しの語を避ける。

通らなかった形と、そのときの答えの順位は次のとおりである。順位は、試した時点の版での値である。

## 4. 群の担当への注意

- 数値と記号: 答えにする値は、数字の末尾を群の数字にする（C1=1 … C8=8、共通=9）。末尾 0 は誰でも使える。帯（110〜199 など）にしなかったのは、点検が部分一致で見るため、先頭の桁ではぶつかるからである（137 kPa は 2137 kPa に含まれる）。
- 共通文書の値を写さない: world.json の reserved_terms の語を群の文書に書くと、共通の問いが「答えの語がほかのチャンクにもある」で落ちる。特に、C5 は計測器の周期、C6 は供給圧力、C8 は区分別の期限と基準逸脱審査会を書かない。
- 書いてはいけない事実: 全力運転の運転時間、ブローバイガス量の許容値、流量係数（world.json の never_write）。書くと unanswerable が成り立たなくなる。
- 共通の問いの起点を守る: world.json の protect_core_entries の場面を、群の文書で同じ言葉で書かない。量産機検査要領の「6. 記録」に成績表の様式番号を書くと、CORE-06 の起点が 3 位から押し出されるおそれがある。
- 並行文書: C1〜C3 は world.json の families の見出しをそのまま使う。見出しのかっこ書きは注意書きであり、見出しには入れない。
- 個票の見出し: 設備や計測器ごとの節は、見出しを管理番号だけにする。名称を見出しに入れると、名称で聞く質問で直接引ける。
- 年月日は 2019.06.12 の形で書く。表紙の改正記号と年月日は、world.json の documents（発行目録と同じ値）に合わせる。

## 5. 弱い点

- 質問の言い回しに敏感である。3. の表のとおり、答えの節の語が 1 語入ると 3〜19 位に上がる。文書の側を直して防げたのは CORE-05 と CORE-07 の一部だけで、残りは質問の語の選び方に頼っている。問いの文を直すときは、avoided_terms を確かめる。
- ent1 と ent2 の余裕は小さい（42〜46 位、条件は 21 位より下）。ref1 と ref2 は 50〜89 位である。
- CORE-09 のつなぎのチャンク（T001 別表 1）は 8 位で、上位 6 件に入らない。答えのチャンク（L001 3.(4)）の「EC」か、L001 2. の「KS-TC-T001 の別表 1 による」をたどって届く想定である。
- CORE-06 と CORE-08 は答えが同じ表（QK-TC-01 別表 2）の別の行である。CORE-07 は起点が T001、答えが P001 で、P001 の 3-4 にも同じ管理番号がある（どちらを起点にしても着く）。
- 点検は全チャンクをリランカーで並べた順位であり、埋め込みと全文検索の候補 20 件を通した順位ではない。群の文書 32 本が加わると、起点の順位と答えの順位は変わる。共通の問いは、全文書をそろえた後にもう一度点検する必要がある。そのとき起点が 3 位を外れても、同じつなぎを持つ群の節が上に来ただけなら、経路は成り立っている。
- 答えの語のうち「29 年」「39 年」「19 稼働日」は 2 けたで、「539」は単位の無い数字である。群の文書に同じ並びが出るとぶつかる。
